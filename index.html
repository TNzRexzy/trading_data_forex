Akun dan Privasi Data

Daftar atau masuk menggunakan email dan password dari layar login. Setelah masuk, jurnal dan checklist tersimpan dengan ID akun Anda; kebijakan RLS membatasi setiap permintaan ke baris milik pengguna tersebut.

  1. Project URL dan publishable key Supabase sudah dikonfigurasi untuk aplikasi ini. Publishable key memang terlihat di browser; jangan pernah menggantinya dengan `service_role` key.
  2. Di Supabase, aktifkan Authentication → Providers → Email dan masukkan URL website ke Site URL serta Redirect URLs pada Authentication → URL Configuration.
  3. Daftar melalui aplikasi menggunakan email pemilik data lama. Jika konfirmasi email aktif, buka tautan verifikasi sebelum masuk.
  4. Backup database, ganti `YOUR_REGISTERED_EMAIL` di supabase-migration.sql dengan email tersebut, lalu jalankan seluruh query terbaru di SQL Editor.
  5. Masuk kembali dan isi pengaturan akun serta rencana fase. Setelah disimpan, saldo/proyeksi baru tampil dari nilai Supabase yang Anda masukkan.
  6. Pengguna berikutnya dapat mendaftar; pengaturan, jurnal, dan arus kas mereka terpisah per akun.
Semua baris lama tanpa pemilik dipindahkan ke satu akun yang ditentukan. Pilih email pemilik yang benar dan backup database terlebih dahulu. Jangan pernah memakai `service_role` key di browser.

Konfigurasi Sekali dan Hosting

URL project dan publishable key Supabase sudah diatur pada konfigurasi aplikasi, bukan dimasukkan pengguna lewat formulir. Publishable key memang tersedia di sisi browser untuk aplikasi statis; keamanan data berasal dari autentikasi dan RLS, bukan merahasiakan key ini.

  1. Project URL dan publishable key sudah terpasang. Pastikan Anda tidak menggantinya dengan `service_role` key.
  2. Di Supabase, aktifkan provider Email dan atur Site URL serta Redirect URLs pada Authentication → URL Configuration.
  3. Commit file `index.html`, `README.md`, dan `supabase-migration.sql` ke repository.
  4. Aktifkan GitHub Pages lewat Settings → Pages dengan branch `main` dan folder root.
